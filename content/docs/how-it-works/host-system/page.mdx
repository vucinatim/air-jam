# Host System

The Air Jam host system manages game sessions and input routing. This page explains how hosts work in different modes and how input flows through the system.

## Host Modes

### Standalone Host

The simplest mode—your game connects directly to the Air Jam server.

<StandaloneHostDiagram />

**Usage:**

```tsx filename="src/app.tsx"
import { createAirJamApp, env } from "@air-jam/sdk";
import { airjam as game } from "./airjam.config";

export const airjam = createAirJamApp(game, {
  runtime: env.vite(import.meta.env),
});

const HostShell = () => (
  <airjam.Host
    onPlayerJoin={(player) => spawnPlayer(player)}
    onPlayerLeave={(id) => removePlayer(id)}
  >
    <HostView />
  </airjam.Host>
);

// Players' controls reach the game in its simulation steps:
// step: (sim, { input, players }) => players.forEach((p) => process(sim, input(p.id)))
const HostView = () => <GameCanvas />;
```

`createAirJamApp` binds the game declaration from `src/airjam.config.ts` to the
browser and returns `Host`, `Controller` and `paths`.

### Arcade Mode (Outer App + Embedded Game)

In arcade mode, the platform runs the outer Arcade app and your game runs as an embedded Air Jam host inside an iframe.

The important rule is:

1. Arcade owns platform surface state
2. your game owns gameplay state
3. the room owns membership, seats and the latest copy of every channel

<ArcadeModeDiagram />

## One Room, Served to Each Frame

The Arcade's shell is the room's only host. It never hands its connection to a
game: when it shows a game, it serves that game's frame a view of its room over
a `MessagePort`, and each game's controller page gets the same kind of view of
its phone's seat.

- A frame sees and publishes only its own channels: everything outside the
  Arcade's own `arcade.*` channels, such as `airjam.room` and its stores
- A frame that reaches outside its scope is closed `unauthorised`; the room and
  the shell carry on
- A new frame for the same surface replaces the old one, which closes as
  `replaced`
- Which game is showing lives in the shell's `arcade.surface` channel; its
  `epoch` identifies one showing of one game

Your game uses the normal input lane, replicated state lane and signal lane, as
it would standalone.

## Connection Flow

### 1. Arcade Launch

```
[Arcade shell]                [Room]                      [Phone]
    │                             │                            │
    │ hello (host key, seats)     │                            │
    │ ───────────────────────────▶│                            │
    │                             │                            │
    │ welcome { code: "ABCD" }    │                            │
    │ ◀───────────────────────────│                            │
    │                             │                            │
    │  Display QR Code            │                            │
    │  with room code             │     Scan QR Code           │
    │                             │ ◀──────────────────────────│
    │                             │                            │
    │                             │     hello (phone key)      │
    │                             │ ◀──────────────────────────│
    │                             │                            │
    │ seats [p1]                  │     welcome { seat: p1 }   │
    │ ◀───────────────────────────│ ──────────────────────────▶│
```

### 2. Game Launch

```
[Arcade shell]                          [Your Game]        [Phone]
    │                                       │                   │
    │ arcade.surface → { kind: "game" }     │                   │
    │ ─────────────────────────────────────────────────────────▶│
    │                                       │                   │
    │ Load iframe ─────────────────────────▶│                   │
    │                                       │                   │
    │   room bridge request (MessagePort)   │                   │
    │ ◀─────────────────────────────────────│                   │
    │                                       │                   │
    │   serve a scoped view of the room ───▶│                   │
    │                                       │                   │
    │                                       │   Load game UI    │
```

### 3. Active Gameplay

While the game shows, every seat's input reaches your game:

```ts
// Your game's simulation reads controls as usual inside the mounted host runtime.
step: (sim, { input, players }) => {
  for (const player of players) play(sim, player.id, input(player.id));
},
```

#### When a phone drops

A phone that loses its connection keeps its seat while the room waits for it
to come back (two minutes by default). The game hears at once: the player stays
in `players` with `connected: false`, and becomes connected again when the
phone is back. The simulation step also gets `reconnectingPlayerIds`, so each
game decides whether to wait, let a bot cover or carry on:

```ts
step: (sim, { players, reconnectingPlayerIds }) => {
  if (reconnectingPlayerIds.length > 0) return; // hold until everyone is back
  // ...
},
```

Outside the simulation, `getReconnectingPlayerIds(players)` from
`@air-jam/sdk/core` gives the same list from `useAirJamHost()` state.

### 4. Game Exit

```
[Phone]               [Arcade shell]                       [Your Game]
    │                     │                                     │
    │ exit (arcade.surface request)                             │
    │ ───────────────────▶│                                     │
    │                     │ arcade.surface → { kind: "browser" }│
    │                     │ Close the game's view ─────────────▶│
    │                     │ Drop the game's channels            │
    │                     │ Destroy iframe ────────────────────▶│
    │ ◀── Show Arcade controller                                │
```

## Host Registration

### Standalone Mode

```tsx
<airjam.Host roomId="GAME">
  <HostView />
</airjam.Host>;

// Inside HostView:
const host = useAirJamHost();
// host.roomId contains the room code
// host.joinUrl contains full URL for QR code
```

Opening the room stays automatic:

1. local dev: no credential
2. hosted rooms: the SDK fetches a short-lived grant from `hostGrantEndpoint`
   for each room it opens, and sends render-crash reports to the platform
   unless the app passes its own `reportError`
3. after a reload, the host returns to its room with its key and keeps its
   players

Game code does not change between those modes.

### Embedded Game Mode (Arcade)

```tsx
// The SDK detects that it is embedded and asks the page around it for the room.
// Game code should not parse the embedding params directly.
const host = useAirJamHost();

// Closing and switching games belong to the Arcade.
// Game hosts keep gameplay logic in host callbacks and simulation steps.
```

## Player Management

### Player Lifecycle

```tsx
const HostShell = () => (
  <airjam.Host
    onPlayerJoin={(player) => {
      // player.id - The seat the room gave ("p1", "p2", …)
      // player.label - Display name ("Player 1", or the name they chose)
      // player.color - Assigned color ("#FF5733")
      // player.kind - "phone", "preview" or "agent"
      // player.connected - false while the phone is away
      // player.avatarId - Optional chosen avatar
      spawnPlayerEntity(player);
      announceJoin(player.label);
    }}
    onPlayerLeave={(controllerId) => {
      removePlayerEntity(controllerId);
    }}
  >
    <HostView />
  </airjam.Host>
);
```

### Accessing Players

```tsx
// Current player list
host.players.forEach((player) => {
  console.log(player.label, player.color);
});

// Player count
const playerCount = host.players.length;

// Find specific player
const player = host.players.find((p) => p.id === targetId);
```

### Player Colours

Each player starts with a colour the room picks. When the game decides a
player's colour (a team, a stand, a car), it says so, and every device shows
the player that way: the screen's player bar and controller windows, the
player's own phone, and `player.color` in the game and its controllers.

```tsx
host.setPlayerColor(playerId, team === "red" ? "#ef4444" : "#3b82f6");
```

Colours are hex, `#rrggbb`. Draw players from `player.color` so the game
and Air Jam never disagree.

## Controller Presentation State

The host publishes a small presentation for the phones: whether the game is
playing or paused, and how to hold the phone. Networked stores own the real
multiplayer state; a short message for the players is a toast signal or a
store field.

A game whose `inputModalities` include `'joystick'` always gets a landscape controller; the SDK applies it, so do not set orientation; lay it out with `GamepadLayout` from `@air-jam/sdk/ui`: the stick under the left thumb, the actions under the right in a square the same size, and only short status between them.

```tsx
const host = useAirJamHost();
host.pauseRuntime();
host.resumeRuntime();

// Controllers read controller.runtimeState and controller.controllerOrientation
```

## Error Handling

```tsx
const host = useAirJamHost();

// Reconnecting is automatic; show it while it happens
if (host.connectionStatus === "reconnecting") {
  showReconnectUI();
}

// A busy hosted service queues new rooms
if (host.queuePosition !== null) {
  showQueue(host.queuePosition);
}

// Check for errors
if (host.lastError) {
  showError(host.lastError);
}
```
